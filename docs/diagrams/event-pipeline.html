Syslog to Telegram: the live event pipeline

A syslog line survives four real refusal gates before a model ever runs: a recovery is refused as not-a-fault, an unrecognized transition is refused rather than guessed, nineteen of twenty reviewed mnemonics never wake the model at all, and admission refuses replays and flap storms. What gets through reaches MiniMax through a schema with every pinned parameter deleted, not filtered — and the ticket's recorded answer is investigate_lab's own deterministic dependency descent, not a model's paraphrase of it. One ticket, one Telegram thread, per event — mechanically armed today, not a code-level dry run: the gate, the notifier and the model caller are all live wiring, not stubs. Status as of today: B-706 (promote the mnemonic), B-707 (notify lifecycle) and B-717 (delivery gate) are all DONE, closed 2026-08-25 — a controlled acceptance corpus traced real Down events end to end (router buffer → syslog-ng → Loki → watcher → live MCP) with zero-loss delivery, and the operator has since turned notifications on (NETTOOLS_EVENT_NOTIFY=1). Delivery is now durable rather than fire-and-forget: a SQLite-backed event store records every lifecycle transition and leases outbox deliveries for at-least-once send. Remediation intentionally still does not exist: this path investigates and pages a human, and nothing more.

ios-xr-nettools · MCP anatomy

Between a model naming a tool and a device seeing a command

The MCP server (nettools-mcp) is one process with two public shapes — a 37-tool classic compatibility surface and a 6-tool staged surface built for a local model — chosen once at startup and never per-call. Every tool, on either surface, is registered through the same wrapper: it is what applies sanitisation, the inventory gate, the evidence gate, and the active-probe/external-source gates, before the tool's own body ever runs. This page draws that wrapper once, then censuses everything it wraps.

FAIL-CLOSED, STARTUP-ONLY

Two names, one policy

  • mcp_profiles.profile_for() resolves NETTOOLS_MCP_SURFACE: unset defaults to classic (compatibility), any recognised value passes through, and any other, unrecognised value fails closed to staged — the narrower surface, never the wider one.
  • No third profile exists at runtime. GUIDED_TOOL_NAMES/GUIDED_CAPABILITIES is staged's own internal name (label="guided") for the same six tools, not a separate offering.

B-703, ALL THREE LAYERS

The registration gates

  • L1 inventory — any device_name not in lab.yaml is refused before platform, credentials, or a socket resolve.
  • L3 evidence — for asserted-object tools, mcp_epoch_validation.validate_asserted_object() checks evidence_cache.EvidenceCache (10s TTL, 0 = always-live).
  • Manifest parity — a CI test, not a gate a request passes through: it fails the build if the staged registry, PIN_TABLE, and the event loop's offline schema disagree.

B-473 / B-512, DEFAULT-OPPOSITE

The two traffic gates

  • Active probes (get_lab_ping/traceroute/probe_lab) — NETTOOLS_MCP_ALLOW_ACTIVE_PROBES, default off. A model firing an unprompted probe was measured live.
  • External sources (Loki/Prometheus/NetBox/graph, 8 tools) — NETTOOLS_MCP_ALLOW_EXTERNAL_SOURCES, default on. No caller-chosen destination, so no SSRF-shaped risk.

Who consumes which surface

Four callers spawn or connect to nettools-mcp, and none of them gets the server's ambient environment by accident — each chooses, or has chosen for it, exactly what it needs.

HUMAN-DRIVEN

LM Studio

  • Reads the operator's own .env. staged is the recommended profile for a local model; classic (37 tools) is the compatibility default until the surface-level A/B lands.
  • Active probes and external sources follow whatever the operator set for the CLI/MCP more broadly — nothing forces them here.

UNATTENDED

Event loop

  • child_server_env() spawns the child with three values forced regardless of the operator's own .env: NETTOOLS_MCP_SURFACE=staged, NETTOOLS_MCP_ALLOW_ACTIVE_PROBES=0, NETTOOLS_MCP_ALLOW_EXTERNAL_SOURCES=1.
  • Of the 6 staged tools, only 4 are ever offered to the model: explore_lab, check_lab, investigate_lab, history_lab. lookup_lab has no safe pin schema; probe_lab is pinnable but deliberately withheld — a model fired it unprompted once, and this is the second, structural layer that makes that unreachable even if the first (the forced env above) ever failed.

DIAGNOSTIC

CLI inspect

  • nettools inspect forwards the operator's environment verbatim — no env_overrides — and calls classic-surface tools by name (list_lab_devices, check_lab_bgp_neighbors), so it assumes classic is active.

REMOTE, DIRECT HTTP

nettools-mcp (HTTP)

  • A bearer-token-authenticated streamable-http transport (mcp_server/http_api.py), containerized and published directly as plain HTTP on 0.0.0.0:8000 for trusted LAN/VPN clients.
  • No NETTOOLS_MCP_SURFACE is forced in its Compose environment, so it defaults to classic — the same 37-tool surface and registration wrapper as any other classic caller.

What stops a flapping link from becoming a storm

Every event-triggered run passes one atomic, flock-protected gate before any model or tool activity — admission.admit_event_run() checks exact-replay identity (≤1hr) and a sliding-window rate budget (≤6/device or ≤30/fabric per ≤1hr) inside the same lock, because event-triggered runs are separately-spawned OS processes an in-process semaphore can't see across. A completed run's terminal outcome is then recorded by finish_event_run() — a retryable failure frees its event ID sooner than a completed run does. A third, separate gate, the one every SSH collection uses, caps live concurrency at ≤1/device and ≤4/fabric. No refusal is a silent empty success.

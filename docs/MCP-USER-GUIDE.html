IOS-XR Nettools MCP

User Guide for the authenticated, read-only network inspection service

Service status: the MCP service runs in a persistent Docker container on a4000 and exposes native MCP streamable HTTP. It is bound to a4000 loopback by default and is intended to be reached through an SSH tunnel.

What This Service Does

The service exposes reviewed Cisco IOS-XR lab inspection tools through the Model Context Protocol (MCP). It can inspect inventory, interface and routing protocol state, deterministic device health, tickets, logs, metrics, and selected topology sources.

  • Device commands are reconstructed from typed inputs and an allowlist.
  • There is no arbitrary command tool, configuration mode, shell access, or network remediation capability.
  • Raw device command text is sanitized before MCP clients receive results.
  • Active probes are disabled by default.

Connect from a Mac

1. Create an encrypted tunnel

ssh -N -L 8000:127.0.0.1:8000 rami@a4000

Keep this terminal open while using the MCP client. The client endpoint is then:

http://127.0.0.1:8000/mcp

2. Configure an MCP client

Use a client that supports MCP streamable HTTP. Supply the bearer token through the client’s secret store or a local environment variable. Do not place the token in a committed configuration file.

{
  "mcpServers": {
    "ios-xr-nettools": {
      "url": "http://127.0.0.1:8000/mcp",
      "headers": {
        "Authorization": "Bearer ${IOS_XR_NETTOOLS_MCP_TOKEN}"
      }
    }
  }
}

Client configuration formats differ. The essential requirements are the endpoint URL and an Authorization: Bearer <token> header on every MCP request.

Authentication and Access

PropertyCurrent behavior
TransportNative MCP streamable HTTP
AuthenticationShared bearer token; missing or invalid tokens receive HTTP 401
EncryptionThe SSH tunnel encrypts traffic between the Mac and a4000
Network exposureLoopback-only on a4000 by default
AuthorizationAll valid token holders receive the same read surface; there is no per-user RBAC
Do not expose this endpoint directly to the public internet. It does not currently provide TLS termination, per-user identity, token rotation, RBAC, or rate limiting. Share the bearer token only with trusted operators.

Useful First Calls

list_lab_devicesList the lab inventory.

list_lab_ticketsList open tickets. Set include_closed=true to include completed investigations.

Operational Notes

  • The service uses strict SSH host-key verification for routers.
  • Tickets, evidence, admission state, and event state are persisted in a Docker named volume and survive container restart.
  • The service restarts automatically after a host reboot through Docker Compose.
  • NetBox and Neo4j tools use Docker service DNS when those backing services are running. If either backing service is down, its MCP tool returns a structured error.
  • External-source tools depend on the availability of their respective platform services.

Support Checklist

  1. Confirm the SSH tunnel is running.
  2. Confirm the MCP client sends the bearer token.
  3. Call list_lab_devices before a device-specific tool.
  4. For a returned object refusal, refresh the relevant device check and verify the requested object exists.
  5. For NetBox or graph errors, verify the corresponding backing service is running before changing MCP configuration.

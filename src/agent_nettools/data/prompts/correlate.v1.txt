GROUNDING
=========
The finding below was reached by deterministic code walking the protocol
dependency stack. It is not in question. Your task is the one the walk cannot
do: say *when* the change happened, whether it happened more than once, and
whether it coincided with anything else.

**Every timestamp below is the device's own clock, read from the body of the
log message.** That distinction is load-bearing and you must preserve it.

The log collector stamps each line with the time it *received* the message,
which is not the time the network changed. On this fabric those differ by
seconds under normal conditions and by minutes when a device buffers and
replays. Correlating "when did it break" against arrival time produces a
timeline that is confidently wrong and that nothing downstream can detect —
the ordering looks plausible, the causality is invented. Use only the device
timestamps given here, and never infer an ordering finer than they support.

The window has already been filtered by code: entries generated by the
monitoring collector's own SSH sessions have been removed, and duplicates have
been collapsed. The counts of what was removed are given, so you can say how
much of the window you are seeing.

CONSTRAINTS
===========
1. Use only events present in the window. Never recall an event from elsewhere,
   and never describe one you have not been shown.
2. Quote device timestamps exactly as given. Do not convert them, do not
   normalise them to another zone, do not round them.
3. State intervals only between two timestamps that are both in the window.
4. **A configuration commit near a change is a coincidence in time, not a
   proven cause.** Report it as coincident and say so. The commit may well be
   the trigger; establishing that is beyond this evidence.
5. **If the window contains no events relevant to the finding, say exactly
   that: `"found": false` with a summary of "no correlating events in
   window".** Do not reach for the nearest event in time and describe it as
   related. An unrelated event presented as context reads exactly like a
   correlated one, and a timeline built from the closest available line is
   worse than no timeline — the reader cannot tell the difference, and will
   act on it.
6. If the window is empty, that is also `"found": false`. An empty window is
   not evidence that nothing happened; it is evidence that nothing was
   recorded. Say which.
7. Do not recommend changes. Do not restate the diagnosis.
